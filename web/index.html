Evidence discipline

What is visible? What does it prove? What remains unproven?

The interface keeps those questions separate by design. Missing evidence is displayed as a limitation, never silently converted into a fact.

01

Visible

Onchain records, indexed events, network metadata, transaction receipts and explicit public references.

02

Proven

Only the claims that follow directly from the available evidence and its authenticated scope.

03

Unproven

Authority, rules, decisions, purpose, outcomes or impact when the required evidence is absent.

Accountability detail

Six evidence domains are evaluated independently. A stronger state in one domain does not upgrade the others.

Accountability model

Funds → Authority → Rules → Decisions → Outcomes → Evidence

This six-part model predates ETHOnline and belongs to the existing GFC transparency architecture. The new hackathon work is the Explorer that maps live blockchain records into these explicit evidence states.

Verification vocabulary

  • VerifiedEvidence directly supports the stated claim within the displayed scope.
  • Partially verifiableSome technical facts are supported while broader claims remain unproven.
  • Not verifiableThe required evidence is not present in the available data.
  • UnavailableA required source or record is unavailable.
